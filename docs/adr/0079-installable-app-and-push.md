# ADR 0079: Farbaek on phones, an installable app with push notifications

- Status: accepted (2026-10-25).
- Spec Stage 7 asks for native apps: Expo with local workspaces, the Approval Wallet, pairing, Mesh over the local network, push notifications, and the mobile-to-desktop flow.

## Context

Native apps need things this build can't supply:
- **iPhone:** an Apple Developer Program membership ($99 a year) in the owner's name, and a Mac or Expo's cloud builds (an Expo account) to build.
- **Android:** a Google Play developer account ($25 once) to publish.
- **Testing:** real devices.

Each is an account, a payment or hardware only the owner has. Meanwhile, what people most need on a phone is to know when a build or its checks finish, and then review and approve. The web app already does the reviewing and approving at phone widths (44 px targets, the Approval Wallet, ADR 0042).

## Decision

**Farbaek installs as an app now, from the browser.**
- `src/app/manifest.ts` gives it a name, icons (192 px, 512 px and a maskable 512 px, generated by `scripts/brand-assets.mjs`) and full-screen display. It opens Mission Control, with shortcuts to Approvals and New build.
- The root metadata makes it a full-screen Home Screen app on iPhone. The Apple touch icon's edges are now porcelain all the way out: one pass of sharp had left them transparent, which iOS shows as black.

**The service worker (`public/sw.js`):**
- shows the offline page (`/offline`) when a page can't load, and shows notifications;
- caches only that page and an icon, never anything with someone's data;
- opens only Farbaek's own paths when a notification is pressed.

**Push notifications, with no new dependency:**
- **Encryption:** RFC 8291 (aes128gcm), checked byte for byte against the RFC's worked example.
- **Server identification:** RFC 8292 (VAPID, ES256). The key pair is `VAPID_PRIVATE_KEY` when set, or derived with HKDF from the server's Supabase secret, so it works without new configuration.
- **When:** the same moments as email (a build someone started finished, and a change's checks ended), in the email's words, opening the task.

**Devices** (migration v49, `push_subscriptions`):
- Each device's subscription belongs to one person, who reads only their own, and never the keys.
- Only the browsers' push services are accepted, stored or sent to: Google (Chrome and Android), Apple (Safari on iPhone and Mac), Mozilla (Firefox) and Microsoft (Edge on Windows).
- At most ten devices a person. A device the push service calls gone is removed, and so is one after twenty failures in a row.

**Settings > This device:**
- turn notifications on, send a test (10 an hour), or turn them off;
- see every device with notifications on, and turn any of them off.

On iPhone it first explains adding Farbaek to the Home Screen, since Safari offers notifications only to installed sites.

**The Privacy Policy** names the push services and says they carry only encrypted messages.

## What native apps still need

The owner's Apple and Google developer accounts, a build path for iPhone (a Mac or Expo's cloud builds), and real devices for the spec's end-to-end handoff. Mesh between phones and computers over the local network needs a native app too, since browsers can't join it. When those exist, an Expo app can reuse everything here: the same notifications, signed with these VAPID keys, and the same pages for review.

## Consequences

- People can install Farbaek on any phone today, and hear when their work needs them.
- No native app store review, and no per-platform builds to keep up.
- Messages pass through the browser makers' push services, encrypted end to end, so those services see only that a message was sent and when.
