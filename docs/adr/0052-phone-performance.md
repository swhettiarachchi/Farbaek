# ADR 0052: Phone performance, measured

- Status: accepted (2026-10-23).
- Builds on ADR 0008 (White Signal, 3D and motion rules), ADR 0034 (films) and ADR 0051 (film playback on phones).

## Context

The owner asked for Farbaek to stay smooth on less powerful phones, with changes backed by measurements.

**`pnpm qa:vitals` measures in the lab.** It loads pages the way Lighthouse's mobile profile does:
- a 412 × 823 screen;
- a 4× slower CPU;
- 150 ms round trips;
- 1.6 Mbps down.

It loads each page three times on a cold cache and reports the median LCP (with its element), CLS, TBT and FCP, plus bytes by kind.

**The baseline** (main at a0344d7) found four problems:

| Page | What was measured | Why |
| --- | --- | --- |
| Homepage | LCP 4.1 s, TBT 907 ms, FCP 2.6 s | The hero text sat inside a Motion `Reveal` that renders `opacity: 0` on the server, so nothing in the hero painted until JavaScript hydrated. On idle, the 3D scene loaded about 240 KB of script on any device with 4 cores and 4 GB, which is most phones. |
| Task page | TBT 585 ms, 555 KB of JS | Every change in a proposal mounted CodeMirror at once, far below the fold. |
| Every page | A 206 KB image | The favicon was the 512 × 512 PNG. |
| Every public and app page | Motion (43 KB gzipped) in the shared scripts | The public mobile menu used Motion, and the bundler grouped it with shared code. |

## Decision

- **The hero renders visibly from the HTML.** `Reveal` is now a CSS entrance (`reveal-in`) with the same rise and timing, so the hero paints with the page.
- **3D scenes only on screens with a mouse or trackpad.** `canRun3D()` now also needs `(hover: hover) and (pointer: fine)`. Touch-first screens keep the static artwork, the same knight with its orbit.
  - **Measured with the scene off on a phone:**
    - TBT went from 723–929 ms to 184–263 ms;
    - JS went from 527 KB to 286 KB.
  - **The rules:** `CLAUDE.md` and the `farbaek-ui` skill state this.
- **The mobile menu animates with CSS** (`sheet-in`, `sheet-out`, `menu-rise`). Motion now loads only on the homepage, whose sections use it.
- **Diffs mount near the screen.** `WhenNear` mounts each proposal diff (and with it CodeMirror) only within 600 px of the screen. What's approved doesn't change: unmounted files keep their proposed content, as before.
- **The homepage sections below the first screen use `content-visibility: auto`** (`.home-later`). That saved about 350 ms of first paint on the phone profile. It needed two supporting changes:
  - **Anchors:** content-visibility estimates sizes, so an anchor jump would land in the wrong place. `AnchorLayout` lays out every section before an in-page jump (a link click in the capture phase, an arrival with a hash, back and forward), then lands instantly.
  - **Smooth scrolling:** an animated arrival raced that landing, so `scroll-behavior: smooth` now applies only under `html:focus-within`. Clicked links still scroll smoothly; arrivals, route changes and find-in-page jump.
- **Images:**
  - **AVIF first,** then WebP (`images.formats`). The hero art went from 162 KB to 71 KB.
  - **The hero image** has `fetchPriority="high"`.
- **Favicons:** 32 and 48 px icons (1.4 and 2.6 KB) are listed before the 512 px one. They're generated by `scripts/brand-assets.mjs`, scaled from the logo and never redrawn.

## Consequences

**After, against the baseline** (median of three, phone profile):

| Page | LCP (ms) | TBT (ms) | FCP (ms) | JS (KB) | Total (KB) |
| --- | --- | --- | --- | --- | --- |
| / | 4148 → 1988 | 907 → 211 | 2608 → 1492 | 531 → 287 | 1377 → 579 |
| /app | 1372 → 1188 | 139 → 183 | 1372 → 1188 | 292 → 247 | 580 → 339 |
| /app/new | 1288 → 1020 | 120 → 183 | 1288 → 1020 | 292 → 247 | 574 → 334 |
| Task page | 1424 → 1304 | 585 → 226 | 1424 → 1304 | 555 → 351 | 879 → 474 |
| /pricing, /sign-in, /security | about the same | about the same | about the same | about the same | 200 KB less (favicon) |

- **Reading the JS column:**
  - **The figures in the table** count every script that arrived.
  - **`pnpm qa:vitals` now splits them:** scripts the page's own HTML names ("JS"), and the rest ("later"). The rest is mostly Next.js prefetching the pages linked from the screen.
  - **On `/pricing`, for example:** 149 KB is its own and 138 KB comes later, mostly the homepage's scripts, because the header links to it.
  - **Prefetching stays on.** It spends some data on phones in exchange for an instant tap through.
- **Run-to-run noise:** TBT moves by about ±50 ms between runs. The small rises on `/app` and `/app/new` are within that.
- **Lab numbers only:** these come from an emulated phone. Field data (real visitors' Core Web Vitals) isn't collected; that would need consent and a collector, and nothing is added for it.
- **Phones lose the 3D scene.** That's a deliberate trade: the static artwork is the same knight, and the scene's cost lands exactly when people start using the page.
