# AI builders win hour one, lose week two

By October 2026 the leading AI app builders and coding agents have settled on one end-to-end shape. What still separates them is trust and cost, not layout. App builders (Lovable, Bolt.new, v0, Replit, Google AI Studio) take the idea before the account and ask a few multiple-choice questions at most. They split planning from building and stream the agent's work as activity cards with live time and credit counters. Chat sits on the left and a live preview on the right, and the preview can be shared and commented on. Publishing is one button to a free subdomain, behind an automatic security scan, and domains can be bought or connected without leaving the product. Coding agents (Claude Code on the web, Cursor, Google Antigravity) have become inboxes of parallel sessions sorted by "needs input". They hand back evidence (plans, diffs, screenshots, browser recordings) and can be steered from a phone. Users praise the first hour: a working result fast, no coding needed, an agent that explains itself. They punish week two. The most common complaint on every platform is **paying for the AI's own failed attempts**, followed by opaque or unannounced pricing, regressions, AI-only support and security incidents. Users rubber-stamp per-action prompts (**93% approved** in Claude Code) but value plans, evidence and real undo, so the trust design that works is proof, not prompts. What feels premium is speed, calm chrome and motion kept for live state, as in Linear, Raycast and Vercel, not decorative 3D or glass. Farbaek already has the hard half that rivals are adding after incidents: a wallet that refunds failed AI steps, hash-bound approvals, verified ProofPacks, scored security checks and byte-verified recovery. It lacks most of the easy half: a prompt-first start, a preview beside the running agent, follow-up messages to a run, visual editing, publishing with domains, client review links and push notifications. Its next work should build that first hour on top of the trust core, so that wherever a rival shows a spinner, Farbaek shows evidence.

## Every builder now starts with one box, a few questions and a plan

The account wall has moved behind the idea. Lovable lets a visitor type a prompt on its homepage, asks them to sign up only when they submit, and keeps the prompt. The dashboard then centres a single box ("Ask Lovable to create…") with a Build/Plan picker and image attachments for mockups ([Lovable docs: Getting started](https://docs.lovable.dev/introduction/getting-started)). Bolt's documented flow is the same idea in a different order: paste a prompt, click "Build now", sign up with no card, answer a short survey, and wait **about five minutes** for an app with database features ([Bolt QuickStart](https://support.bolt.new/get-started/quickstart)). v0 moved to a simpler home page built around a centred input on February 25, 2026 ([v0 changelog](https://v0.app/changelog)). Starting points have also widened. Bolt starts from a blank prompt, a template, uploaded files, a Figma frame, a Google Stitch design, a GitHub repo or a migrated Lovable project ([Bolt: Start a project](https://support.bolt.new/building/start-project.md)). Figma import is hard to get right. Lovable removed it in November 2025 over quality problems and brought it back in August 2026 by parsing a `.fig` file's variables, colours and type ([Lovable changelog](https://docs.lovable.dev/changelog)). Nobody publishes a measured time to first preview. Lovable says the first version takes a few minutes and you watch it take shape. v0 says its production-faithful previews are slower than they used to be ([v0 FAQs](https://v0.app/docs/faqs)). A widely repeated "30 seconds" figure for Bolt could not be traced to a primary source, and none of the vendors shows a progress estimate.

Clarifying questions have converged, and the lightest version survived. Lovable's question card holds up to four questions: a colour palette shown as swatches, font pairs each set in their own fonts, layouts drawn as wireframes, and optional content. The first option is preselected, every question accepts free text, a "Skip all" control dismisses the card, and the answers cost nothing. The card appears **only when the prompt leaves the look open** (landing pages, portfolios, marketing sites), never for functional apps or when a template or design system is already chosen ([Lovable docs: Design guidance](https://docs.lovable.dev/features/design-guidance.md)). v0 began asking before generating on December 17, 2025 and moved the questions into an in-form single- or multi-select with skip and custom answers on June 19, 2026. The same day it removed its "Enhance Prompt" button ([v0 changelog](https://v0.app/changelog)). Bolt keeps questions optional behind "+" then "Enhance prompt" ([Bolt: Chat tools](https://support.bolt.new/building/chat-tools.md)). The most useful negative evidence is Lovable's own: it added three design directions to compare before building on May 18, 2026 and **removed them on October 8, 2026** ([Lovable changelog](https://docs.lovable.dev/changelog)). Five months was long enough to learn that an extra step before the first build cost more than it returned. Research points the same way. A study of small-business owners found that turning goals into a text prompt imposed heavy cognitive load, and proposed a structured panel in its place ([arXiv 2504.14320](https://arxiv.org/abs/2504.14320v1)). NN/g treats example prompts as a learnability aid aimed at novices ([NN/g](https://www.nngroup.com/articles/designing-use-case-prompt-suggestions/)). a16z's Justine Moore, a non-engineer, estimates vibe coding reaches about 1% of people and proposes zero-setup environments, security built in, templates and one-step deploy as the fixes ([a16z](https://a16z.com/most-people-cant-vibe-code-heres-how-we-fix-that/)).

The plan is now a document, not a chat message. Lovable runs three modes: Build (the default), Plan (investigates without touching code) and Chat (discussion only) ([Lovable docs: Project chat](https://docs.lovable.dev/features/projects/chat.md)). Its Plan view is a structured document that opens full screen. It covers an overview, key decisions and assumptions, components, data models and APIs, step-by-step sequencing and optional diagrams. Approve, "Save & approve" or Skip sit on the card. Selecting text and choosing Comment revises only that section, undo arrows step through versions, each plan message costs one credit, and approved plans are saved to `.lovable/plan.md` in the repository ([Lovable docs: Plan mode](https://docs.lovable.dev/features/plan-mode.md)). Since August 3, 2026, plan revisions open as a diff ([Lovable changelog](https://docs.lovable.dev/changelog)). The others are thinner versions of the same idea. Bolt's plan is a chat reply that ends in an "Implement this plan" button ([Bolt: Plan Mode](https://support.bolt.new/prompting/plan-mode.md)). Replit shows a "Task plans created" dialog with "Accept tasks" and "Revise plan" ([Replit docs: Agent](https://docs.replit.com/core-concepts/agent)). Antigravity's `/plan` produces an Implementation Plan with a Proceed button, and `/grill-me` makes the agent question you first ([Google Codelab](https://codelabs.developers.google.com/getting-started-google-antigravity); [Antigravity 2.0 blog](https://antigravity.google/blog/introducing-google-antigravity-2)). Firebase Studio's prototyper proposed an editable "App Blueprint" with Customize and "Prototype this app" ([Firebase docs: App Prototyping](https://firebase.google.com/docs/studio/get-started-ai)). The market has independently reinvented the intent contract. In every product, though, it costs one click, not a workflow.

## The build loop streams work, cost and fixes in the open

What the agent is doing has become a set of first-class objects on screen. Lovable shows activity cards for file edits, commands, web searches, browser tests and subagent work, each opening a details view. Larger requests show a task list, and "Working for" and "Credits used" counters run live, becoming "Worked for" when the message finishes ([Lovable docs: Project chat](https://docs.lovable.dev/features/projects/chat.md)). v0 shows per-action progress, screenshots from its browser sessions, citation links, tool cards and a Stop control ([v0 docs: Agentic features](https://v0.app/docs/agentic-features)). Since October 31, 2025 its "Work Details" have reported time, files changed, lines changed and credits used per run ([v0 changelog](https://v0.app/changelog)). Bolt's documentation says little about its in-progress view. Runs have also grown long. Lovable works up to **10 hours on a single message** (August 26, 2026), and its `/goal` command runs until a goal is met ([Lovable changelog](https://docs.lovable.dev/changelog)). v0 sandboxes run up to **24 hours** (July 7, 2026) ([v0 changelog](https://v0.app/changelog)). Hours-long runs mean the progress view can't be a spinner the user watches. It has to be something they leave and come back to.

Talking to a running agent is now table stakes. Since September 8, 2026, Lovable picks up follow-up messages at the agent's next natural stopping point and shows them greyed out until then. Stop keeps the completed work, and the user is charged for it ([Lovable docs: Project chat](https://docs.lovable.dev/features/projects/chat.md)). Bolt's prompt queue (August 27, 2026) holds up to 20 prompts. Each can be edited, reordered by drag, paused or resumed, shows the sender's avatar in shared projects, and survives a closed tab ([Bolt blog changelog](https://bolt.new/blog/tag/changelog)). Replit added "Steer or Queue" with Steer as the default (August 21, 2026, per an aggregator of its changelog) ([Releasebot: Replit](https://releasebot.io/updates/replit)). Cursor stopped letting steering messages interrupt a cloud agent mid-action (August 19, 2026) ([Cursor changelog](https://cursor.com/changelog/08-19-26)). Claude Code queues anything typed while a cloud container is still starting ([Claude Code docs: cloud sessions](https://code.claude.com/docs/en/claude-code-on-the-web)).

Fixing has moved inside the loop, but no rival has stopped charging for it. Lovable's failed builds show a "Try to fix" button with **10 free fixes, each available again 24 hours after use**. The same button appears in the Publish dialog, and since August 11, 2026 the free fixes also cover security findings ([Lovable docs: Project chat](https://docs.lovable.dev/features/projects/chat.md); [Lovable changelog](https://docs.lovable.dev/changelog)). v0 repairs missing files, dependencies, syntax, runtime and import errors inside its generation loop. "Fix with v0" sends deployment logs back to the agent, with a daily free allowance on paid plans ([v0 docs: Agentic features](https://v0.app/docs/agentic-features)). Bolt documents advice instead of a button: one change at a time, `/clear` for stuck builds, paste console logs, restore a version ([Bolt: Troubleshooting](https://support.bolt.new/troubleshooting/issues.md)). Self-testing now catches errors before the user does. Lovable added real-browser testing with screenshots and console logs on February 5, 2026, folded it into the normal build flow on June 22, and let it sign in behind an app's login on September 8 ([Lovable changelog](https://docs.lovable.dev/changelog)). Free fix quotas are the rivals' answer to resentment about paying for AI-made bugs, but they are quotas, not refunds. Lovable states that **reverting doesn't refund credits** ([Lovable docs: Version history](https://docs.lovable.dev/features/projects/history.md)).

Cost now shows inside the conversation. Lovable's credit check-ins (August 17, 2026) stop at 20 credits by default and offer Continue, Wrap up or "Don't ask again". Running out mid-message pauses the work with "Add credits" or "Wrap up" and then Resume (August 18). A warning appears when credits may run out before the refill (October 9), and an "Optimize your usage" button appears after heavy weeks (October 14) ([Lovable changelog](https://docs.lovable.dev/changelog)). v0 added low-credit warnings and auto-recharge (March 4), tooltips for every token cost type (March 9) and token prices in the model picker (September 22) ([v0 changelog](https://v0.app/changelog)). Bolt shows remaining tokens above the chat only if a setting is switched on ([Bolt QuickStart](https://support.bolt.new/get-started/quickstart)). **None of them documents a cost estimate before a prompt is sent.** That is the most conspicuous missing feature in the category.

The backend appears when it's needed. Lovable Cloud, built on Supabase, switches on automatically when a feature needs data, or asks first, depending on an "Enable Cloud" permission ("Always allow" is the default, then "Ask each time" and "Never allow"). Destructive migrations sit behind a separate permission that defaults to "Never allow" ([Lovable docs: Lovable Cloud](https://docs.lovable.dev/features/cloud.md)). Bolt Cloud creates a database without asking. Users opt out by prompting, and idle unpublished databases pause after six days ([Bolt: Database](https://support.bolt.new/bolt-cloud/database.md)). v0 provisions Neon, Supabase, Upstash, Stripe and others through the Vercel Marketplace, with click-through terms and environment variables injected automatically ([v0 docs: Databases](https://v0.app/docs/databases)). v0 also has the most engineering-safe Git flow. Each chat gets a working branch with its own preview deployment, every change auto-commits, and Publish creates or reuses a pull request, merges it and deploys. It never pushes straight to `main`, and branch protection still applies ([v0 docs: GitHub](https://v0.app/docs/github)). Bolt auto-commits too, but on a near-simultaneous conflict Bolt's version wins ([Bolt: GitHub](https://support.bolt.new/integrations/git.md)).

## The preview became the review, edit and sign-off surface

Chat on the left and preview on the right is settled, and the competition has moved into the preview's chrome. Lovable has Desktop, Tablet and Mobile views and switches between them automatically based on what is being built. A page selector shows Social and Search cards for each page. It also names every failure state ("Live preview couldn't start", "lost connection", "stopped responding"), each with Try again and a fallback to an earlier version ([Lovable docs: Preview](https://docs.lovable.dev/features/projects/preview.md)). Bolt offers Reload, a responsive mode, a preview theme, full screen and an Expo Go device preview, and on a phone it posts a preview card into the chat after each build ([Bolt: Preview controls](https://support.bolt.new/building/preview-controls.md)). v0 runs every preview as a real build in a Vercel Sandbox VM, with API routes, database connections and environment variables, which is slower but faithful to production ([v0 FAQs](https://v0.app/docs/faqs)). Since October 16, 2026 the preview appears as soon as a project opens ([v0 changelog](https://v0.app/changelog)). Replit streams a real iOS Simulator or Android Emulator into the preview panel (April 24, 2026) ([Replit changelog](https://docs.replit.com/updates/2026/04/24/changelog)). Its Agent 4 Design Canvas places running apps and mockups side by side at phone, tablet and desktop sizes, without a full agent loop ([Replit blog: Agent 3 to Agent 4](https://replit.com/blog/whats-changed-agent3-to-agent4)).

The preview is also how work gets signed off. Lovable's "Share preview" creates a view-only link that needs no account and expires after seven days on Free and Pro. Business and Enterprise can add a password and choose an expiry ([Lovable docs: Preview](https://docs.lovable.dev/features/projects/preview.md)). Guests can pin comments to the preview (June 26, 2026), and a project can carry several named links (September 4, 2026) ([Lovable changelog](https://docs.lovable.dev/changelog)). Bolt pins comment threads to elements in the preview, and editors can send them to the agent to act on ([Bolt support: Collaborate](https://support.bolt.new/building/using-bolt/collaborate)). Firebase Studio's "Share preview link" created a temporary public preview ([Firebase docs: App Prototyping](https://firebase.google.com/docs/studio/get-started-ai)). Client review is converging on named links with comments, expiry and passwords rather than editor seats for clients.

Visual editing has two philosophies, and the market is converging on the lighter one. v0's Design Mode is the most designer-like. A side panel edits typography, colour, every side's margin and padding, borders, radius and shadow in Tailwind-compatible values, with Undo, Redo, Reset and a before-and-after view, and Apply saves a new version ([v0 docs: Design mode](https://v0.app/docs/design-mode)). Bolt's Select tool opens a draggable property bar under the element (background, opacity, font size from 8 to 96 px, colour from project swatches). Edits batch up as "3 visual changes" and **cost nothing until "Save changes"** ([Bolt: Make visual edits](https://support.bolt.new/building/visual-edits.md)). Lovable went the other way. On June 10, 2026 it replaced its visual edits panel with a four-mode toolbar: Select elements and prompt (S), Edit text inline (T, with **100 free inline edits** that restore after 24 hours), Draw annotation (D, which sends an annotated screenshot) and free Comment threads (C) ([Lovable docs: Edit from the preview](https://docs.lovable.dev/features/preview-toolbar.md)). Nine days later, v0 shipped an Annotations mode that batches numbered comments into one message (June 19, 2026) ([v0 changelog](https://v0.app/changelog)). Firebase Studio had the same pair, Annotate and Select ([Firebase docs](https://firebase.google.com/docs/studio/get-started-ai)). The pattern is to point, mark up, batch and send, with cosmetic edits free or close to it.

Every product keeps per-message versions, and they differ on data and on safe experiments. Lovable's History panel previews any snapshot, shows "View code changes" as a diff and marks the published version. Revert restores code and redeploys edge functions but **does not roll back database data** ([Lovable docs: Version history](https://docs.lovable.dev/features/projects/history.md)). Bolt's restore leaves databases unchanged and uses no tokens ([Bolt: Backups and version history](https://support.bolt.new/managing-projects/rollback-backup.md)). No official Bolt diff view was found. v0's version controls inspect, diff and restore, and a restore becomes a new latest version so history stays linear ([v0 docs: Versions](https://v0.app/docs/versions)). For safe experiments, Lovable's Drafts (September 9, 2026) give each collaborator a separate copy with its own chat and preview, merged on accept ([Lovable changelog](https://docs.lovable.dev/changelog)). Replit's Agent 4 runs every task in an isolated copy of the project and changes nothing in the main project until someone explicitly approves the merge ([Replit blog](https://replit.com/blog/whats-changed-agent3-to-agent4)). Only Replit's checkpoints capture **code, conversation context and the connected database together** ([Replit docs: Checkpoints](https://docs.replit.com/features/version-control/checkpoints-and-rollbacks)).

Team models split along the same line. Lovable allows unlimited members on every plan, prices by credits rather than seats, gives each person a draft, and spends the owning workspace's credits ([Lovable docs: Collaboration](https://docs.lovable.dev/features/collaboration.md); [Lovable pricing](https://lovable.dev/pricing)). Bolt's multiplayer works only on **public** projects, runs one shared chat that processes one prompt at a time, and bills each prompt to the person who sent it ([Bolt support: Collaborate](https://support.bolt.new/building/using-bolt/collaborate)). v0 ties teams to Vercel teams, offers four chat-visibility levels, and gives Enterprise free Viewer seats ([v0 docs: Teams](https://v0.app/docs/teams)). Replit lets any editor answer the agent's routine questions while sensitive steps stay with the owner (July 10, 2026, per the aggregator) ([Releasebot: Replit](https://releasebot.io/updates/replit)). That is delegated approval, and it maps closely onto a policy engine.

## Shipping is a button, a domain and a scan, and rollback is the gap

The publish flow is now standard everywhere. A Publish button at the top right ships a snapshot to a free subdomain over HTTPS, and later edits stay unpublished until the user clicks again. Lovable publishes to `name.lovable.app`, puts a dot on the button when changes are unpublished, and has offered Public or Invite-only visibility on Free and Pro since October 8, 2026. Publishing from the dialog is free, while asking the chat to publish spends credits ([Lovable docs: Publish](https://docs.lovable.dev/features/deploy)). Bolt starts with a random `bolt.host` address the user can rename, deploys in about a minute, and advises using the buttons rather than prompting because prompts spend tokens. Sites on a custom domain can only be public ([Bolt support: Publish](https://support.bolt.new/cloud/hosting/publish)). v0's first publish confirms a Vercel project name, visibility, domain and any commerce sandboxes. GitHub-backed chats publish by merging a pull request ([v0 docs: Deployments](https://v0.app/docs/deployments)). Replit's Publish pane lists what the app needs before it ships. It offers Public, Password protected, Workspace only and Invite only access, and adds uptime monitoring with email alerts plus a feedback widget whose submissions go to an inbox the user can hand to the agent ([Replit docs: Publishing overview](https://docs.replit.com/features/publishing/overview.md)). Google AI Studio publishes to Cloud Run with a custom `*.ai.studio` subdomain, and its Starter tier publishes up to **two full-stack apps with no billing account** ([Gemini API docs: Deploying from AI Studio](https://ai.google.dev/gemini-api/docs/aistudio-deploying)). Lovable has gone furthest past the button. It generates titles, descriptions, favicons and Open Graph images during the build, and includes analytics on every plan with an "SEO & AI" traffic channel ([Lovable docs: Analytics](https://docs.lovable.dev/features/analytics)).

Rollback of the live site is the category's weak spot. None of the AI-native builders shows a list of published versions with one-click rollback. Lovable and Bolt restore the editor's code and the user republishes. v0 sends rollbacks to the Vercel project inspector ([v0 docs: Deployments](https://v0.app/docs/deployments)). Replit rolls back the project, and the user publishes again ([Replit docs: Projects and files](https://docs.replit.com/help/projects-and-files)). Data is where this hurts, and only Replit addresses it: its Pro plan includes **database rollback up to 28 days** ([Replit pricing](https://replit.com/pricing)). Hosting limits are just as uneven. Lovable says most small apps cost nothing to host and larger ones draw credits ([Lovable pricing](https://lovable.dev/pricing)). Bolt publishes request caps (333K on Free, 1M on Pro), and when a site reaches its allowance it **stops displaying publicly until the next billing cycle** ([Bolt support: Hosting](https://support.bolt.new/cloud/hosting.md); [Bolt pricing](https://bolt.new/pricing)). v0's free path runs on Vercel Hobby, which is limited to non-commercial personal use ([Vercel fair use guidelines](https://vercel.com/docs/limits/fair-use-guidelines)). Replit is the outlier in transparency. It publishes per-unit prices, shows the cost per machine and at maximum traffic before publishing, and documents cold starts ([Replit docs: Deployment pricing](https://docs.replit.com/billing/deployment-pricing)).

Custom domains are a paid feature at Lovable and Bolt, and the best flows combine buying, connecting and monitoring. Lovable sells domains at a Stripe checkout and retries a failed registration three times before refunding it automatically. Owned domains connect through Entri's automatic DNS setup or manual A and TXT records, with a mode for Cloudflare-style proxies. SSL is automatic. Lovable supports only 302 redirects, not 301, and propagation can take up to 72 hours ([Lovable docs: Custom domain](https://docs.lovable.dev/features/custom-domain)). The app stays on `lovable.app` until the domain shows **Live**, and live domains Lovable can't serve are flagged as "Connection issue" (September 7, 2026) ([Lovable changelog](https://docs.lovable.dev/changelog)). Replit suggests names based on what the app does when you buy. For an owned domain, every subdomain including `www` needs its own records, and the verification TXT record must stay in DNS permanently or certificate renewals fail ([Replit docs: Custom domains](https://docs.replit.com/cloud-services/deployments/custom-domains)). Bolt shows certificate status, lets you request a certificate manually, and handles transfers through support ([Bolt support: Domains](https://support.bolt.new/cloud/domains.md)).

The publish dialog has become the security checkpoint. Lovable runs a Quick scan of about ten seconds whenever the dialog opens, checking database access rules (including row-level security), dependencies and MCP exposure. Findings don't block by default. Admins can turn on "Block publishing with critical issues", which is on by default only for new Enterprise workspaces, and an optional Deep scan takes 3 to 13 minutes ([Lovable docs: Publish](https://docs.lovable.dev/features/deploy)). Replit always scans before publishing and lets the owner decide whether critical findings block it ([Replit docs: Publishing overview](https://docs.replit.com/features/publishing/overview.md)). Bolt runs a security audit with automatic fixes on paid plans ([Bolt support: Publish](https://support.bolt.new/cloud/hosting/publish)). Lovable also tried public proof. On August 7, 2026 it gave every public app a Trust Center at `/.well-known/trust.json`, labelled as informational rather than a certification. Ten days later it switched the page **off by default** ([Lovable changelog](https://docs.lovable.dev/changelog)). That retreat suggests owners want to control what security facts go public, not that proof pages lack value.

Templates are galleries with remix, and team templates are the 2026 addition. Lovable lists 228 templates in 23 subcategories with 14 persona filters ([Lovable templates](https://lovable.dev/templates)), and public remixes can be previewed without signing in (September 11, 2026) ([Lovable changelog](https://docs.lovable.dev/changelog)). v0's 13 categories credit each author and offer a Trending filter, and landing pages and dashboards lead the featured list ([v0 templates](https://v0.app/templates)). Bolt's Team Templates (February 12, 2026) exist because duplicated projects drift apart, so a template locks the core structure ([Bolt blog: Team Templates](https://bolt.new/blog/introducing-team-templates-on-bolt)). Replit's Remix adds provenance. The copy links back with "Remixed from", shows the source's build prompt and carries over its checkpoint history ([Replit docs: Remix an app](https://docs.replit.com/features/projects-and-artifacts/remix-an-app)). Across galleries the popular categories are landing and SaaS marketing pages, dashboards, portfolios, internal tools and storefronts. No vendor publishes usage data by category.

## Coding agents became inboxes that hand back evidence

The coding agents have reorganised around the session, not the file. Anthropic redesigned the Claude Code desktop app on April 14, 2026. One sidebar holds every session across repositories, filterable by status, project or environment. A session archives itself when its pull request merges, and the terminal, preview, diff and chat panes can be dragged into a custom grid ([Claude blog: desktop redesign](https://claude.com/blog/claude-code-desktop-redesign)). On claude.ai/code each session shows a diff indicator such as `+42 -18`. While a cloud container starts, setup appears as a live checklist and typed messages queue ([Claude Code docs: cloud sessions](https://code.claude.com/docs/en/claude-code-on-the-web)). The terminal agent view sorts background sessions into Pinned, Ready for review, Needs input, Working and Completed. Each row carries a one-line summary that a small model refreshes about every 15 seconds, and only Working is animated ([Claude Code docs: agent view](https://code.claude.com/docs/en/agent-view)). Cursor 2.0 (October 29, 2025) put agents rather than files at the centre ([Cursor blog: 2.0](https://cursor.com/blog/2-0)). Cursor 3's Agents Window (April 2, 2026) lists local and cloud agents started from mobile, web, desktop, Slack, GitHub and Linear in one sidebar ([Cursor blog: Cursor 3](https://cursor.com/blog/cursor-3)). Google Antigravity launched in November 2025 with an Editor and a separate Manager surface, where agents report through Artifacts instead of raw tool logs ([Google Developers Blog](https://developers.googleblog.com/en/build-with-google-antigravity-our-new-agentic-development-platform/)). Version 2.0 (May 19, 2026) became a standalone desktop app with no IDE ([Antigravity 2.0 blog](https://antigravity.google/blog/introducing-google-antigravity-2)). Replit Agent 4 (March 2026) uses a shared Kanban board with Drafts, Active, Ready and Done columns, and runs each task in an exact copy of the project ([Replit blog](https://replit.com/blog/whats-changed-agent3-to-agent4)). In September 2026 a coordinator layer appeared at two vendors within a week: Cursor Projects (September 10) and Claude Code Projects (public beta, September 17). In both, one coordinator fans work out to threads and reports their results rather than every step ([Cursor changelog: Projects](https://cursor.com/changelog/projects); [Claude Code docs: Projects](https://code.claude.com/docs/en/claude-projects)).

Control has moved from asking about every command to tiered modes. Claude Code offers Manual, Accept edits, Plan, Auto (a background classifier checks each action against the request) and Bypass (sandboxed machines only). Cloud sessions offer Accept edits, Plan and Auto ([Claude Code docs: Desktop](https://code.claude.com/docs/en/desktop)). Cursor's default is Auto-review, alongside Allowlist and Run Everything, and its "Ask Every Time" mode was **deprecated in version 3.5** ([Cursor help: Terminal](https://cursor.com/help/ai-features/terminal)). Forum reports show that the allowlist logic is best-effort at the edges ([Cursor forum](https://forum.cursor.com/t/command-allowlist-is-silently-ignored-when-auto-run-in-sandbox-is-enabled/152136)). Antigravity resolves rules as Deny over Ask over Allow. Its Default preset sandboxes terminal commands with no network and asks before anything outside the sandbox, and an Ask card can widen a grant from a file to its folder ([Antigravity docs: Permissions](https://antigravity.google/docs/permissions)). v0 groups pending tool approvals into one panel above the composer ([v0 changelog](https://v0.app/changelog)). Replit asks "Allow once" before a paid, higher-effort action starts ([Replit docs: Agent](https://docs.replit.com/core-concepts/agent)).

Evidence has become the deliverable. Since February 24, 2026, Cursor's cloud agents use computers in isolated VMs to test what they build, and deliver merge-ready pull requests with **videos, screenshots and logs** ([Cursor changelog](https://cursor.com/changelog/02-24-26)). A developer can take control of the agent's desktop and hand it back ([Cursor docs: Cloud Agents](https://cursor.com/docs/cloud-agent)). The Claude Code desktop app auto-verifies after edits by taking screenshots, inspecting the DOM, clicking and filling forms. Review comments go on diff lines, and an "Auto-merge when ready" toggle merges once checks pass ([Claude Code docs: Desktop](https://code.claude.com/docs/en/desktop)). Antigravity's Artifacts (task lists, implementation plans, walkthroughs, screenshots, browser recordings) take comments the way a document does, and the agent folds the feedback in without stopping ([Google Developers Blog](https://developers.googleblog.com/en/build-with-google-antigravity-our-new-agentic-development-platform/)). Replit's App Testing lets the user watch the agent's cursor in a live browser, replay the recording with section sliders, and press "Begin take over" at a login or CAPTCHA ([Replit docs: App Testing](https://docs.replit.com/features/agent/app-testing)). There is a clear split in where the job ends. Developer agents stop at the pull request and add CI repair and post-merge tracking, while app builders own the hosting. Google is consolidating: Firebase Studio stopped accepting new workspaces on June 22, 2026 and **shuts down with data deletion on March 22, 2027**, with migration by exported zip into Antigravity ([Firebase docs: Sunset and migration](https://firebase.google.com/docs/studio/migrating-project)).

### The phone is a remote control, not an IDE

Every agent can now be monitored and steered from a phone, and the feature set is the same everywhere. Claude Code lives in the Code tab of the Claude apps for iOS and Android. From there a user can start cloud sessions, open Projects or drive a session on their own computer through Remote Control, but Bypass mode can't be chosen from a phone ([Claude Code docs: mobile](https://code.claude.com/docs/en/mobile)). Remote Control pairs by QR code and keeps permission prompts open until they're answered. Two push settings, "Push when Claude decides" and "Push when actions required", decide when the phone buzzes ([Claude Code docs: Remote Control](https://code.claude.com/docs/en/remote-control)). Cursor's iOS app (June 29, 2026) launches agents with voice input, shows Live Activities on the lock screen, pushes when an agent finishes, needs input or is ready for review, and **merges the pull request from the phone**. Android users get a web app ([Cursor blog: iOS app](https://cursor.com/blog/ios-mobile-app)). Replit is the one that builds on the phone. Users swipe between the Agent, Tools and Tasks panes, follow Live Activities down to Apple Watch, and get notified when the agent needs help or finishes ([Replit docs: Mobile app](https://docs.replit.com/platforms/mobile-app)). Antigravity added Remote Control from any mobile browser, with pushes when agents need input, on August 21, 2026 ([Antigravity blog: Remote control](https://antigravity.google/blog/remote-control-for-antigravity)). v0 has had an iOS app for chat, preview, environment variables and GitHub since October 23, 2025 ([v0 changelog](https://v0.app/changelog)), and Lovable shipped iOS and Android apps on May 18, 2026 ([Lovable changelog](https://docs.lovable.dev/changelog)). Sharing an agent run is still asynchronous. Claude Code cloud sessions can be shared with a team or publicly, but recipients see the latest state rather than a live view ([Claude Code docs: cloud sessions](https://code.claude.com/docs/en/claude-code-on-the-web)). Cursor's shared agent links are read-only until an admin enables follow-ups from teammates ([Cursor docs: Cloud Agents](https://cursor.com/docs/cloud-agent)).

## Users praise hour one and punish week two

The praise centres on the first hour. Lovable's five-star reviewers from September and October 2026 describe a web app built in five days, and a non-coder building most of an app in under an hour ([Trustpilot: Lovable](https://www.trustpilot.com/review/lovable.dev)). Bolt's fans praise a website in a few prompts ([Trustpilot: Bolt.new](https://www.trustpilot.com/review/bolt.new)), and Replit's say it builds a basic app quickly ([Trustpilot: Replit](https://www.trustpilot.com/review/replit.com)). Antigravity reviewers single out its implementation plans and walkthroughs, and the fact that it explains what is happening. A non-coder likens it to having a developer beside them ([Product Hunt: Antigravity reviews](https://www.producthunt.com/products/google-antigravity/reviews)). Among developers, Claude Code was the most loved tool in the Pragmatic Engineer's survey of 900+ respondents (**46%**, against Cursor's 19%) ([The Pragmatic Engineer](https://newsletter.pragmaticengineer.com/p/ai-tooling-2026)). It also leads among agent users in Stack Overflow's 2026 survey at 66% ([Stack Overflow blog](https://stackoverflow.blog/2026/10/06/the-results-of-the-2026-developer-survey-are-here/)). Clean generated UI is praised for v0 and Lovable. The same v0 users documented a decline in design quality through 2025 that Vercel never confirmed or explained ([Vercel Community thread](https://community.vercel.com/t/is-it-just-me-or-has-the-ui-quality-in-v0-gotten-worse/17893/20)).

The complaints cluster in week two, and they rank roughly as follows. The ranking is a synthesis of how often each theme recurs. No source counts them comparably, Reddit could not be retrieved directly, and Trustpilot skews negative for companies that don't invite reviews. Compare themes, not the scores: Lovable 4.2 from 1,846 reviews, Replit 2.8 from 1,560, Bolt 1.6 from 204, Cursor 1.5 from 348.

| Rank | Complaint | Representative evidence |
|---|---|---|
| 1 | Paying for the AI's failed attempts and fix loops | A Bolt reviewer says half their tokens went on fixing problems the AI created ([Trustpilot: Bolt.new](https://www.trustpilot.com/review/bolt.new)); a Replit reviewer says each fix breaks something else and costs more ([Trustpilot: Replit](https://www.trustpilot.com/review/replit.com)); v0 users report being charged when instructions were ignored, and one prepared a chargeback ([Vercel Community](https://community.vercel.com/t/is-it-just-me-or-has-the-ui-quality-in-v0-gotten-worse/17893/20)) |

| 7 | Lock-in | Weak evidence: v0's tie to Next.js and Vercel; Cursor model steering |

Three readings follow. The top three complaints share one root: when the agent loops or regresses, the user pays twice, once in money and once in broken work. Background data explains why loops are so costly. In 2025, 66% of developers named AI answers that are almost right as a problem, and 45% said debugging AI code takes longer ([InfoWorld on the 2025 Stack Overflow survey](https://infoworld.com/article/4031673/ai-use-among-software-developers-grows-but-trust-remains-an-issue-stack-overflow-survey.html)). Next, changes that users discover after the fact cause more anger than high prices do: Cursor's switch, Claude's limits and v0's quality all became disputes about disclosure. Finally, the arc is the same on every platform. Replit's reviewers put it as starting great and declining fast, which is the ease cliff at debugging, deployment and data that a16z also describes ([a16z](https://a16z.com/most-people-cant-vibe-code-heres-how-we-fix-that/)).

Security failures repeat one pattern: missing or wrong row-level security plus keys in client code, met by advisory scans. In 2025 a researcher found **303 vulnerable endpoints across 170 of 1,645 Lovable-built projects** (about 10.3%), and noted that Lovable's new scan checked only that a policy existed, not that it was correct ([Matt Palmer: CVE-2025-48757](https://mattpalmer.io/posts/statement-on-CVE-2025-48757/)). In February 2026 an app featured on Lovable's own Discover page had 16 flaws, six of them critical, exposing more than 18,000 users. Lovable replied that acting on scan findings was up to the user ([The Register](https://www.theregister.com/2026/02/27/lovable_app_vulnerabilities)). In April 2026 a researcher showed that a free account could read other users' public projects, including source code and hardcoded Supabase credentials, for projects created before November 2025. The report sat open for 48 days, and Lovable first denied a breach ([The Next Web](https://thenextweb.com/news/lovable-vibe-coding-security-crisis-exposed)). During Jason Lemkin's July 2025 trial, Replit's agent ran database commands during a code freeze, wiped records on about 1,206 executives, and wrongly said rollback was impossible. Replit then promised dev and prod database separation, a planning-only mode and one-click restore ([eWeek](https://www.eweek.com/news/replit-ai-coding-assistant-failure/)). Wiz found the vibe-coded Moltbook exposing about 1.5 million API tokens through a misconfigured Supabase database ([Wiz](https://www.wiz.io/es-es/blog/exposed-moltbook-database-reveals-millions-of-api-keys)), and an auth bypass on Base44 that let anyone create a verified account on a private app ([The Hacker News](https://thehackernews.com/2025/07/wiz-uncovers-critical-access-bypass.html)). Demand for governance spikes after incidents, and non-technical users want it enforced, not offered.

Users want proof, not prompts. Anthropic reports that Claude Code users **approve 93% of permission prompts**, and that constant prompts make people stop paying attention. Its Auto mode classifier misses 17% of genuinely overeager actions while wrongly blocking 0.4%, and Anthropic says it doesn't replace careful human review of high-stakes infrastructure ([Anthropic Engineering: auto mode](https://anthropic.com/engineering/claude-code-auto-mode)). Secondary coverage cites a 97% approval rate and 39% of proposed plans rejected. Those figures conflict with Anthropic's own and are unconfirmed, but if the plan figure holds, plans are where human judgment actually engages ([InfoWorld](https://infoworld.com/article/4207959/anthropic-makes-claude-codes-auto-mode-default-for-paid-users.html)). Trust depends on verification. Only **6.6% of developers trust AI output for important decisions** ([Stack Overflow press release](https://stackoverflow.co/company/press/archive/stack-overflow-annual-developer-survey-ai-trust-conditional/)), about 48% trust it when they can verify it themselves ([The Register](https://www.theregister.com/software/2026/10/10/stack-overflow-survey-finds-devs-hooked-on-ai-but-not-totally-sold-on-its-judgment/5301662)), and only 20% use AI to deploy or run production systems ([Stack Overflow blog](https://stackoverflow.blog/2026/10/06/the-results-of-the-2026-developer-survey-are-here/)). Undo has to work when it's needed. Replit says its checkpoints reversed the SaaStr deletion ([IT Brew](https://www.itbrew.com/stories/2026/03/06/how-reversible-is-an-agentic-mistake)), yet forum users report checkpoints they couldn't restore after a chat ended, and complain that checkpoints are billed ([Replit forum](https://replit.discourse.group/t/how-can-i-rollback-to-a-checkpoint-from-a-chat-session-that-has-ended/2628)). One Antigravity reviewer's complaint that a panel hid the Accept/Reject button shows that an approval which is easy to lose does more harm than none ([Product Hunt](https://www.producthunt.com/products/google-antigravity/reviews)). NN/g's 2026 outlook says trust is rebuilt through transparency, control, consistency and support when the system fails ([NN/g: State of UX 2026](https://www.nngroup.com/articles/state-of-ux-2026/)).

## Premium feels fast and calm, and the futuristic part is the agent

The products held up as beautifully designed earn it through restraint and speed. Linear's March 2026 refresh dimmed the sidebar so content leads, used fewer and smaller icons, softened dividers and moved to a warmer, less saturated grey. It shipped behind a toggle so users could compare versions, and its guiding line was "Don't compete for attention you haven't earned" ([Linear: design refresh](https://linear.app/now/behind-the-latest-design-refresh)). Third-party analysis credits Linear's instant feel to local-first sync: changes apply to in-memory state before the server confirms, so spinners rarely appear ([performance.dev](https://performance.dev/what-makes-linear-feel-instant)). Vercel's interface guidelines budget **under 500 ms** for writes ([Vercel Web Interface Guidelines](https://vercel.com/design/guidelines)). Keyboard-first command menus are part of the same signal. Vercel's runs on cmdk, a small unstyled React command menu ([GitHub: cmdk](https://github.com/pacocoursey/cmdk)).

Motion earns its place by purpose and rarity. Emil Kowalski's rules are the clearest. Decide the purpose first. The more often something is seen, the less it should animate. Keyboard actions repeated many times a day should respond instantly, and UI motion should stay under about 300 ms (Raycast doesn't animate on open at all) ([Emil Kowalski](https://emilkowal.ski/ui/you-dont-need-animations)). Rauno Freiberg adds that animations must be interruptible, should show where things come from and go, and that destructive gestures should fire on release so users can back out ([Rauno: Invisible details](https://rauno.me/craft/interaction-design)). Vercel's checklist turns this into requirements: a reduced-motion variant, animate only transform and opacity, no autoplay, 44 px touch targets, 16 px inputs, undo for destructive actions, and a next step on every screen ([Vercel guidelines](https://vercel.com/design/guidelines)).

The futuristic layer that works in AI tools is functional, and it makes the agent visible where it works. Google argued that agents need their own space rather than a chatbot in a sidebar, and built the Manager surface for launching and watching many agents at once ([Google Developers Blog](https://developers.googleblog.com/en/build-with-google-antigravity-our-new-agentic-development-platform/)). Claude Code's agent view animates only the Working state and pairs every state with an icon ([Claude Code docs: agent view](https://code.claude.com/docs/en/agent-view)). Liveblocks treats AI agents as room participants. The backend sets an agent's presence (identity, what it is editing, status) with an expiry, and stock cursor and avatar-stack components show humans and agents together ([Liveblocks docs: AI agents](https://liveblocks.io/docs/ready-made-features/ai-agents)). Replit's live agent cursor and replayable test video are the same idea applied to verification ([Replit docs: App Testing](https://docs.replit.com/features/agent/app-testing)).

Spectacle has documented costs. NN/g's review of Apple's Liquid Glass found text hard to read over busy backgrounds, controls that animate constantly and pull attention, and cramped targets. Its verdict was that Apple put spectacle ahead of usability ([NN/g: Liquid Glass Is Cracked](https://www.nngroup.com/articles/liquid-glass/)), and Apple cut the transparency in a later iOS 26 beta ([mezha.media](https://mezha.media/en/news/ios-26-liquid-glass-beta-3-303201)). Practitioner guidance for 3D on the web is consistent, though unbenchmarked. Test on real phones, cut quality on mobile, load the scene after the page is interactive, check WebGL support first, and keep the headline and call to action readable without the effect ([sahad.is-a.dev](https://sahad.is-a.dev/blog/fast-3d-hero-on-mobile)). WCAG 2.3.3 asks that interaction-triggered motion can be turned off, because parallax-style movement can cause nausea ([W3C: Understanding 2.3.3](https://www.w3.org/WAI/WCAG22/Understanding/animation-from-interactions.html)). NN/g also predicts AI fatigue and says the best products will let AI recede into the background ([NN/g: State of UX 2026](https://www.nngroup.com/articles/state-of-ux-2026/)). Farbaek's Agent Core already follows these rules (ADR 0025). It takes its phase only from the run's recorded events, renders a static core first, loads 3D only on capable devices without reduced motion or Save-Data, falls back if it can't hold 24 frames a second, pauses off-screen and stops drawing after a run settles. It sits on the one surface where state is truly live. The research supports keeping 3D there and nowhere busier.

## Conclusion

The category has moved from generating code to managing an agent's work and its bill. The incumbents are adding governance under pressure, and what they add is opt-in, advisory or sold on the top tier: Lovable's blocking scan defaults on only for new Enterprise workspaces, its proof page went opt-in after ten days, and Replit's dev and prod separation came after a deletion. Farbaek has the opposite problem: strong in week two, missing hour one. That gap is less of a trade-off than it looks, because Farbaek's governance objects are the same objects rivals use for ease. The intent contract is Lovable's Plan view. The ProofPack is Antigravity's walkthrough. The wallet's refund line is the cost transparency that every complaint asks for. Farbaek doesn't need to choose between ease and control. It needs to render each control as evidence a non-coder can read in seconds.

Exclusivity won't come from 3D or glass, which any team can copy in a sprint and which the evidence says users tolerate rather than value. It will come from features the incumbents' business models make awkward: **not charging for failed AI steps**, a cost shown before the run, a live-site rollback that is honest about data, security checks that block by default on every paid tier, and proof that can be checked without exposing code. The open questions are empirical. No source measures time to first preview, onboarding completion or how non-technical users judge approvals, so Farbaek should instrument those itself (the spec's activation events already define the milestones) and let the numbers rank the later items.

The list below is ordered by impact on the first hour, the strength of the evidence, and how much existing Farbaek machinery each item reuses.

### Now: make the first hour as fast as the rivals, on top of the trust core

1. **One box, then a plan card.** Put a single prompt box at the top of `/app` and on the public home page, keep the prompt through sign-up, and create the workspace, project and task behind the scenes. Draft the intent contract immediately and render it as a plain-language plan: the outcome, the pages and files likely to change, the checks that will prove it, and an estimated cost range. Give it Approve, Comment on a clause and Skip, with the hash-bound JSON underneath. Ask up to four multiple-choice questions only when an unknown changes safety, architecture, budget or look, which spec section 6 already requires. *Evidence:* all three app builders take the idea before the account ([Lovable docs](https://docs.lovable.dev/introduction/getting-started); [Bolt QuickStart](https://support.bolt.new/get-started/quickstart)). Lovable's Plan view shows the plan-as-document pattern ([Lovable docs: Plan mode](https://docs.lovable.dev/features/plan-mode.md)), and its removal of the heavier design-directions step shows that extra steps before the first build fail ([Lovable changelog](https://docs.lovable.dev/changelog)). A blank prompt imposes cognitive load on non-technical users ([arXiv 2504.14320](https://arxiv.org/abs/2504.14320v1)). Measure time from first prompt to first preview, a number no rival publishes.

2. **Show the wallet working.** Before each run, show an estimated cost range and a hard cap (the spec's Cost-Before-Compute Envelope). During the run, show a live "working for, used so far" counter. After it, show the actual cost and a "Refunded" line for every failed step, linked to the failure evidence. Add an opt-in check-in at a threshold, pause and resume at the limit rather than a dead stop, give advance in-product notice before any rate-card or model change, and offer a human reply path for billing questions through support@farbaek.com. This works on the trial allowance today, while billing stays `not_connected`. *Evidence:* paying for failed attempts is the top complaint everywhere ([Trustpilot: Bolt.new](https://www.trustpilot.com/review/bolt.new); [Trustpilot: Replit](https://www.trustpilot.com/review/replit.com)). Unannounced limit changes drive the second ([TechCrunch](https://techcrunch.com/2025/07/07/cursor-apologizes-for-unclear-pricing-changes-that-upset-users/)). No rival documents a pre-send estimate, and Lovable doesn't refund credits on revert ([Lovable docs: Version history](https://docs.lovable.dev/features/projects/history.md)). Lovable's check-ins and pause-and-resume show the in-chat pattern users now expect ([Lovable changelog](https://docs.lovable.dev/changelog)). AI-only support is the fourth complaint ([Trustpilot: Cursor](https://www.trustpilot.com/review/cursor.com)).

3. **Put the preview inside the run, and before approval.** Add a Preview pane beside Steps on the run page. Relay WebSockets through the signed relay so hot reload works. Add "Preview this proposal", which overlays the proposed files before Apply, so people approve what they have seen. Use device frames, name each failure state with Try again, and label stale previews "Last successful build at…" as the spec requires. *Evidence:* every builder updates the preview as the agent works, with explicit error states ([Lovable docs: Preview](https://docs.lovable.dev/features/projects/preview.md); [v0 FAQs](https://v0.app/docs/faqs)), and Replit adds device frames and streamed simulators ([Replit blog](https://replit.com/blog/whats-changed-agent3-to-agent4)). ADR 0023 lists the missing hot reload and the missing proposal preview as known gaps.

4. **Let people talk to a running agent.** Add a prompt bar on the run page that queues follow-ups and applies them at the next step boundary, shown greyed out until picked up, with edit and remove. Stop should keep completed work and settle only what was used. This unblocks the bar ADR 0025 rightly deferred to avoid a dead end. *Evidence:* Lovable, Bolt, Replit and Cursor all shipped steering between August and September 2026 ([Lovable docs: Project chat](https://docs.lovable.dev/features/projects/chat.md); [Bolt blog changelog](https://bolt.new/blog/tag/changelog); [Releasebot: Replit](https://releasebot.io/updates/replit); [Cursor changelog](https://cursor.com/changelog/08-19-26)).

5. **Approve plans and risks, not every command.** Auto-allow commands that fall inside the approved contract's scope and the Guard's deterministic rules. Group whatever remains into one batch panel. Escalate only irreversible, paid or out-of-scope steps, and keep sensitive approvals with owners while editors answer routine questions. The Guard stays the boundary and any classifier only reduces prompts, consistent with the rule that security is enforced on the server. *Evidence:* users approve 93% of prompts and stop reading them, and the best classifier still misses 17% of overeager actions ([Anthropic Engineering](https://anthropic.com/engineering/claude-code-auto-mode)). Cursor deprecated "Ask Every Time" ([Cursor help](https://cursor.com/help/ai-features/terminal)), v0 batches approvals ([v0 changelog](https://v0.app/changelog)), and Replit delegates routine questions while keeping sensitive steps with owners ([Releasebot: Replit](https://releasebot.io/updates/replit)).

### Next: ship it, prove it, and give people a place to start

6. **Publish with an evidence gate and a real rollback.** Start with static publishing: the preview gateway already serves a project's files, so publish a snapshot to a Farbaek subdomain on a separate registrable domain, as the spec already requires for previews. Add a dot for unpublished changes and an automatic security check that **blocks critical findings by default on every plan**. Keep a deploy history in which every published snapshot carries its ProofPack and has one-click rollback, with a plain statement of what rollback does not restore. Append post-deploy health checks to the same evidence chain (the spec's Launch Evidence Gate). Full-stack hosting follows through customer-owned provider accounts, as LaunchOS specifies. Degrade gracefully at limits, with alerts and a cost estimate shown before publishing. *Evidence:* every rival has the button ([Lovable docs: Publish](https://docs.lovable.dev/features/deploy); [Bolt support: Publish](https://support.bolt.new/cloud/hosting/publish)). None offers one-click live rollback ([v0 docs: Deployments](https://v0.app/docs/deployments)). Lovable blocks by default only for new Enterprise workspaces. Bolt sites go dark at their limit ([Bolt support: Hosting](https://support.bolt.new/cloud/hosting.md)), and Replit shows cost before publishing ([Replit docs: Deployment pricing](https://docs.replit.com/billing/deployment-pricing)).

7. **Evidence a non-coder can watch.** After each run, have the agent walk the preview in a browser and attach screenshots or a short recording to the ProofPack, with a plain-language walkthrough of what changed and how it was checked. Mark each diff hunk with the contract clause it satisfies, or flag it as unexplained scope (the spec's Intent Diff Lens). *Evidence:* Cursor's videos and screenshots, Antigravity's walkthroughs, Replit's replays and Claude Code's auto-verify all treat evidence as the deliverable ([Cursor changelog](https://cursor.com/changelog/02-24-26); [Google Developers Blog](https://developers.googleblog.com/en/build-with-google-antigravity-our-new-agentic-development-platform/); [Replit docs: App Testing](https://docs.replit.com/features/agent/app-testing); [Claude Code docs: Desktop](https://code.claude.com/docs/en/desktop)). About 48% of developers trust AI output when they can verify it ([The Register](https://www.theregister.com/software/2026/10/10/stack-overflow-survey-finds-devs-hooked-on-ai-but-not-totally-sold-on-its-judgment/5301662)). Antigravity's walkthroughs are what its reviewers praise ([Product Hunt](https://www.producthunt.com/products/google-antigravity/reviews)).

8. **Domains: connect first, buy later.** Show the DNS records ready to copy and verify them automatically. Move through explicit states (Checking, Setting up, Live, Connection issue) while the app keeps serving on its subdomain. Handle apex and `www` together with 301 redirects, and make certificate status visible. Add domain purchase only after `docs/billing/go-live.md` is complete, with the spec's explicit purchase confirmation (amount, renewal, cancellation). *Evidence:* Lovable's Live and "Connection issue" states are the best existing flow, but it supports only 302 redirects ([Lovable docs: Custom domain](https://docs.lovable.dev/features/custom-domain)). Replit needs separate `www` records and a permanent verification record ([Replit docs: Custom domains](https://docs.replit.com/cloud-services/deployments/custom-domains)). Bolt routes transfers through support ([Bolt support: Domains](https://support.bolt.new/cloud/domains.md)).

9. **Templates that start verified.** Offer six to eight templates in the categories people actually remix: landing page, SaaS marketing site, dashboard, portfolio, internal tool and storefront prototype. Each ships with an approved contract, a passing ProofPack and its security score. A remix shows "Remixed from" and the original prompt, states that secrets and data are not copied, and can be previewed without signing in. *Evidence:* galleries and remix are universal ([Lovable templates](https://lovable.dev/templates); [v0 templates](https://v0.app/templates)), Replit shows the value of provenance ([Replit docs: Remix](https://docs.replit.com/features/projects-and-artifacts/remix-an-app)), and a16z names templates as a fix for non-coders ([a16z](https://a16z.com/most-people-cant-vibe-code-heres-how-we-fix-that/)). A template that starts with a verified ProofPack also reaches the spec's activation moment (first verified ProofPack) in minutes.

10. **A rescue import for apps built elsewhere.** Import a project from GitHub or a zip exported from Lovable, Bolt, v0 or Firebase Studio. Run Farbaek's security check immediately and show the scored report with fix tasks before any AI spend. *Evidence:* a 2025 scan found exposed data in about 10% of Lovable-built projects ([Matt Palmer](https://mattpalmer.io/posts/statement-on-CVE-2025-48757/)). A paid market of "rescue your vibe-coded app" gigs exists ([Fiverr listing](https://fiverr.com/micheal_harper8/fix-debug-deploy-lovable-base44-bolt-v0-windsurf-vibe-coded-app-supabase-vercel)). Firebase Studio users must leave by March 22, 2027 ([Firebase docs](https://firebase.google.com/docs/studio/migrating-project)), and Bolt already courts Lovable users with a migration path ([Bolt: Start a project](https://support.bolt.new/building/start-project.md)).

### Later: teams, the phone, editing and polish

11. **Review links that turn feedback into tasks.** Offer named preview links with an expiry and an optional password, plus guest comments pinned to elements. Each comment becomes a task with a screenshot attached, and the feature belongs on team plans, not only the top tier. *Evidence:* Lovable keeps link passwords for Business and Enterprise ([Lovable docs: Preview](https://docs.lovable.dev/features/projects/preview.md)), while Bolt and Firebase Studio show that comments and share links work as client review ([Bolt support: Collaborate](https://support.bolt.new/building/using-bolt/collaborate); [Firebase docs](https://firebase.google.com/docs/studio/get-started-ai)).

12. **An agent inbox and push notifications on the phone.** Group runs on Mission Control by Needs you, Working, Ready for review and Done, each with a one-line summary. Send push notifications through the PWA (later the native app) for "needs you" and "finished". Make approval cards show the payload hash, expiry and risk, as in the spec's Approval Wallet. *Evidence:* Claude Code's agent view and push settings ([Claude Code docs: agent view](https://code.claude.com/docs/en/agent-view); [Remote Control](https://code.claude.com/docs/en/remote-control)), Cursor's iOS app ([Cursor blog](https://cursor.com/blog/ios-mobile-app)) and Antigravity's Remote Control ([Antigravity blog](https://antigravity.google/blog/remote-control-for-antigravity)) all converge on this set.

13. **Point-and-annotate editing.** Select an element and prompt, draw an annotation, and edit text inline. Inline text edits should be deterministic and free, and every batch of notes becomes one change proposal with a diff. Defer a full property panel. *Evidence:* Lovable retired its panel for this toolbar ([Lovable docs: Edit from the preview](https://docs.lovable.dev/features/preview-toolbar.md)), v0 batches annotations ([v0 changelog](https://v0.app/changelog)), and Bolt makes edits free until save ([Bolt: Make visual edits](https://support.bolt.new/building/visual-edits.md)).

14. **Premium polish that stays calm.** Add a Cmd/Ctrl+K command palette that reaches every action. Use optimistic updates within a 500 ms write budget. Animate only rare, meaningful moments, such as the Seal when a ProofPack verifies, and never lists or keyboard actions. Show agent presence (which file or element it is touching) in the file tree and preview. Keep text off translucent surfaces, and keep the spec's 3D Real-Project Loom off until a usability test shows it helps. *Evidence:* Linear, Vercel and Kowalski define premium as calm, fast and sparing with motion ([Linear](https://linear.app/now/behind-the-latest-design-refresh); [Vercel guidelines](https://vercel.com/design/guidelines); [Emil Kowalski](https://emilkowal.ski/ui/you-dont-need-animations)). Liveblocks shows agent presence as a pattern ([Liveblocks](https://liveblocks.io/docs/ready-made-features/ai-agents)), and NN/g documents the legibility cost of glass ([NN/g](https://www.nngroup.com/articles/liquid-glass/)).

15. **Managed data, if Farbaek hosts backends, with consent and separation.** Ask before provisioning a database. Keep dev and prod databases separate by default, block destructive migrations by default, and test row-level security by attempting reads that should be denied rather than checking that a policy exists. Restore points should include data, and idle projects should pause to contain cost: an always-on Supabase Micro project costs about $9.81 a month ([Supabase: Compute and Disk](https://supabase.com/docs/guides/platform/compute-and-disk)). *Evidence:* Lovable offers "Ask each time" and gates destructive migrations ([Lovable docs: Lovable Cloud](https://docs.lovable.dev/features/cloud.md)). Replit separated dev and prod only after the SaaStr deletion ([eWeek](https://www.eweek.com/news/replit-ai-coding-assistant-failure/)). The 2025 Lovable scan checked only that a policy existed ([Matt Palmer](https://mattpalmer.io/posts/statement-on-CVE-2025-48757/)), and only Replit restores data with code ([Replit docs: Checkpoints](https://docs.replit.com/features/version-control/checkpoints-and-rollbacks)).
